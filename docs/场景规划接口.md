# 场景规划接口

## 作品叙事规划

- `POST /api/works/{workId}/narrative-plans`：创建草稿。
- `GET /api/works/{workId}/narrative-plans/current`：读取当前发布版。
- `GET /api/works/{workId}/narrative-plans/latest-draft`：读取最新草稿；没有草稿时响应 `data=null`。
- `GET /api/works/{workId}/narrative-plans/{planId}`：读取指定版本。
- `PUT /api/works/{workId}/narrative-plans/{planId}`：使用 `baseVersion` 编辑草稿。
- `POST /api/works/{workId}/narrative-plans/{planId}/publish`：使用 `baseVersion` 发布。

## 章节场景规划

- `POST /api/chapters/{chapterId}/scene-plan-candidates`：基于当前作品规划和章节大纲 revision 创建 Agent 候选任务。
- `GET /api/chapters/{chapterId}/scene-plan-candidates/latest`、`GET .../{planId}`：读取候选。
- `PUT .../{planId}`、`POST .../{planId}/abandon`、`POST .../{planId}/publish`：编辑、放弃或发布候选。
- `GET /api/chapters/{chapterId}/scene-plans/current`、`GET /api/chapters/{chapterId}/scene-plans/{planNo}`：读取当前或指定已发布版本。

候选和发布使用乐观锁。`scene_plan_generation` 只负责生成候选：成功时候选为 `ready`，关联的 Agent Step、Run 与 AI Task 均为 `succeeded`；人工编辑和发布由既有候选接口独立完成。模型输出只保存结构化 ScenePlan，不保存隐藏推理；作品规划或章节大纲发生变化后不能发布旧候选。

## 场景修订与章纲候选桥接

- `POST /api/chapters/{chapterId}/scene-plan-candidates/from-current` 只克隆同章当前已发布场景规划，生成不关联 AI Task 的 `ready` 修订草稿。`sourcePlanId`、来源版本和 `idempotencyKey` 会持久化；重复同源请求复用原草稿。
- `POST /api/chapters/{chapterId}/scene-plan-candidates/{planId}/outline-revision-candidates` 要求草稿版本、当前章纲 revision 和已完成的一致性报告完全匹配。服务端比较已发布来源与草稿，持久化确定性的场景增删、移动和字段变化，再调用现有章纲调整候选流程。
- 桥接接口只创建候选，不确认章纲、不发布场景规划。章纲候选仍需调用现有显式确认接口；确认后的来源传播会把受影响场景规划标记为需要复核。

### 场景内容 schema

- `ScenePlanView.contentSchemaVersion` 标识每个场景叶子的内容版本。V31 迁移前的历史记录为 v1；模型生成和人工保存的新记录统一为 v2。
- v2 在既有目标、冲突、结果与章纲节拍之外增加 `readerMustKnow`、`causalPreconditions`、`locationTransition`、`stateChanges`、`continuityConstraints`、`narrativeWeight`、`optionalExpression` 和 `doNotInvent`。
- `narrativeWeight` 只允许 `core`、`supporting`、`transition`。六类新增列表字段最多 20 项，每项最多 500 字；`locationTransition` 最多 1000 字。列表和位置承接可以为空，但非空项不得是空白内容。
- 读取 v1 时，缺失列表返回空列表、缺失位置承接返回空字符串、缺失叙事权重返回 `unspecified`。这些兼容值表示“未标注”，不会被写回为推断事实；v2 写入不接受 `unspecified`。
- 模型响应中的人物、地点、设定与伏笔引用必须来自本次固化上下文；没有来源的引用会在持久化前被确定性丢弃，不会改写成其他事实。`seed` 且伏笔 ID 为空时仅表示待人工确认的新伏笔候选。
- 人工编辑按 `sceneKey` 原位更新或恢复场景叶子，保留稳定的 `scenePlanId`；请求中真正移除的场景才会被软删除。
- 场景模型只创建 `ready` 候选。编辑、发布与一致性门禁保持原有显式人工操作，不会因新增语义自动发布规划或确认正文。

生成失败通过既有 AI Task 与 Agent Run 查询接口返回安全错误码：`SCENE_PLAN_PROVIDER_FAILED`、`SCENE_PLAN_JSON_INVALID`、`SCENE_PLAN_VALIDATION_FAILED`、`SCENE_PLAN_PERSISTENCE_FAILED` 或 `SCENE_PLAN_OUTLINE_STALE`。模型调用记录以内部 `llm_model_calls.id` 关联 Agent Step，并且不暴露完整 Prompt 或模型正文。
