**版本**：V1.2  
**日期**：2026-07-05  
**适用范围**：墨契 Web App 后端 P0 主流程当前库结构

## 一、适用范围

本文档描述墨契 Web App 后端 P0 主流程的当前数据库结构，重点包括：

- 当前有哪些表。
- 每张表做什么。
- 每个字段是什么意思。
- 表之间如何关联。
- 典型业务数据如何存储。

## 二、全局约定

### 2.1 主键与时间字段

所有业务表默认使用自增 `id` 作为主键和表间关联键。

所有业务表默认包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT AUTO_INCREMENT` | 主键 ID，数据库内部关联使用。 |
| `gmt_create` | `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间。 |
| `gmt_modified` | `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP` | 更新时间，记录更新时自动刷新。 |

当前 P0 数据库不保留 `biz_id`。接口、服务和表间关系统一使用自增 `id`。

### 2.2 通用控制字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `deleted` | `TINYINT NOT NULL DEFAULT 0` | 逻辑删除标记，`0` 表示未删除，`1` 表示已删除。 |
| `version` | `INT NOT NULL DEFAULT 0` | 通用乐观锁版本号。章节正文当前使用 `chapters.version` 控制保存冲突。 |
| `revision` | `INT NOT NULL DEFAULT 0` | 资源内容修订版本。当前用于 `chapter_outlines` 的大纲编辑冲突控制。 |

### 2.3 JSON 字段边界

当前 P0 不把所有结构都拆成子表。以下内容使用 JSON 保存：

- `chapter_outlines.outline_content`：正式章节大纲结构。
- `chapter_generations.basis_snapshot_json`：生成正文时使用的大纲和约束快照。
- `user_configs.config_value`：用户配置值。

如果 JSON 内部字段以后变成稳定查询条件，再通过独立 issue 拆列或拆表。

## 三、表关系总览

当前数据库共有 23 张业务表：

| 表名 | 中文名 | 作用 |
| --- | --- | --- |
| `works` | 作品表 | 保存作品基础信息。 |
| `chapters` | 章节表 | 保存章节基础信息和正文。 |
| `chapter_outlines` | 章节大纲表 | 保存用户确认、可编辑、可用于生成正文的正式章节大纲。 |
| `chapter_outline_candidates` | 章节大纲调整候选表 | 保存待确认的大纲调整结果及其基础快照、差异和影响。 |
| `chapter_conversations` | 章节会话表 | 保存章节共创或章节编辑 AI 会话。 |
| `chapter_conversation_messages` | 章节会话消息表 | 保存会话内的用户、助手、系统消息。 |
| `chapter_briefs` | 章节共创收束摘要表 | 保存 AI 或会话收束出的摘要、候选结构卡或中间结果。 |
| `chapter_generations` | 章节正文生成记录表 | 保存基于大纲生成正文的任务参数、依据快照和生成结果。 |
| `user_configs` | 用户配置表 | 保存用户级模型配置、写作偏好、外观和同步配置。 |
| `llm_credentials` | 大模型加密凭据表 | 保存与普通配置分离的 AES-GCM 密文、nonce、keyId 和安全摘要。 |
| `ai_tasks` | AI 异步任务表 | 保存 AI 回复、正文生成、大纲刷新等异步任务状态。 |
| `agent_runs` | Agent 运行表 | 保存可恢复工作流的归属、输入快照、状态、超时和幂等键。 |
| `agent_run_steps` | Agent 步骤表 | 保存稳定步骤键的每次执行尝试、状态、摘要与错误。 |
| `agent_checkpoints` | Agent checkpoint 表 | 保存可版本化 JSON 状态和 Run 内单调恢复顺序。 |
| `agent_interruptions` | Agent 人工中断表 | 保存等待确认请求、恢复令牌哈希、版本、结果和过期时间。 |
| `work_narrative_plan_versions` | 作品叙事规划版本表 | 保存作品级目标、前提、冲突和约束的草稿与发布历史。 |
| `chapter_plan_versions` | 章节场景规划版本表 | 保存绑定作品规划和章节大纲版本的候选与发布状态。 |
| `scene_plan_versions` | 场景规划叶子节点表 | 保存一个章节规划版本中的有序 ScenePlan。 |
| `setting_candidates` | 待确认设定表 | 保存从正文、会话或生成结果中抽取出的候选设定。 |
| `setting_entries` | 作品级正式设定表 | 保存用户确认后的正式人物、地点、组织、规则和物品等设定。 |
| `foreshadowing_items` | 伏笔与线索表 | 保存伏笔、线索、来源位置和回收状态。 |
| `chapter_summaries` | 章节摘要表 | 保存每章摘要、人物变化、新增设定和未决问题。 |
| `chapter_key_events` | 章节关键事件表 | 保存每章关键事件，用于后续时间线和上下文检索。 |

核心关系：

```text
works 1 - N chapters
chapters 1 - 1 chapter_outlines
chapters 1 - N chapter_outline_candidates
chapters 1 - N chapter_conversations
chapter_conversations 1 - N chapter_conversation_messages
chapters 1 - N chapter_briefs
chapters 1 - N chapter_generations
chapter_outlines 1 - N chapter_generations
chapter_outlines 1 - N chapter_outline_candidates（基础和确认结果引用）
works 1 - N setting_candidates
works 1 - N setting_entries
works 1 - N foreshadowing_items
chapters 1 - 1 chapter_summaries
chapters 1 - N chapter_key_events
ai_tasks 可关联 message / generation / outline candidate 的异步结果
works 1 - N agent_runs
chapters 0 - N agent_runs
ai_tasks 0 - 1 agent_runs
agent_runs 1 - N agent_run_steps
agent_runs 1 - N agent_checkpoints
agent_runs 1 - N agent_interruptions
```

阶段判断：

- 当前库已覆盖 P0 写作主流程与第一版必通知识层，可保存作品、章节正文、章节大纲、章节摘要、关键事件、设定、伏笔、会话、生成记录和 AI 任务基础状态。
- 角色状态快照、叙事线程、时间线事件和知识巡检结果尚未落库，属于第一版核心增强或后续独立能力。
- 当前接口文档应围绕已落库表和当前 P0 流程生成；编辑建议、LLM 调用日志、token 汇总、角色状态、叙事线程、时间线和知识巡检只作为后续能力说明，不生成当前正式接口。

## 四、表设计详情

### 4.1 `works` 作品表

作用：

- 保存作品基础信息。
- 作为章节、大纲、会话、生成记录的作品级根节点。
- 当前不保存章节数、总字数等统计冗余字段。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 ID。 |
| `title` | `VARCHAR(255)` | 作品标题。 |
| `status` | `VARCHAR(32)` | 作品状态，默认 `draft`。 |
| `deleted` | `TINYINT` | 是否删除。 |
| `version` | `INT` | 乐观锁版本号。 |
| `gmt_create` | `DATETIME` | 创建时间。 |
| `gmt_modified` | `DATETIME` | 更新时间。 |

索引：

| 索引 | 字段 | 作用 |
| --- | --- | --- |
| `idx_works_status_gmt_modified` | `status, gmt_modified` | 按状态和更新时间查询作品。 |

### 4.2 `chapters` 章节表

作用：

- 保存章节标题、序号、正文和工作流状态。
- `content` 是章节正文唯一事实源。
- 不拆段落主表，段落结构由前端或运行时派生。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 ID。 |
| `work_id` | `BIGINT` | 所属作品 ID，关联 `works.id`。 |
| `title` | `VARCHAR(255)` | 章节标题。 |
| `chapter_no` | `INT` | 章节序号，同一作品内唯一。 |
| `chapter_type` | `VARCHAR(32)` | 章节类型：`dedication` 献词，`prologue` 序幕，`chapter` 正文，`epilogue` 尾声，`other` 其他。 |
| `content` | `LONGTEXT` | 章节正文，章节内容唯一事实源。 |
| `workflow_status` | `VARCHAR(32)` | 章节工作流状态，默认 `co_creation`。 |
| `deleted` | `TINYINT` | 是否删除。 |
| `version` | `INT` | 章节正文保存的乐观锁版本号。 |
| `gmt_create` | `DATETIME` | 创建时间。 |
| `gmt_modified` | `DATETIME` | 更新时间。 |

索引与约束：

| 名称 | 字段 | 作用 |
| --- | --- | --- |
| `uk_chapters_work_id_chapter_no` | `work_id, chapter_no` | 保证同一作品内章节序号唯一。 |
| `idx_chapters_workflow_status` | `work_id, workflow_status` | 查询作品下指定工作流状态章节。 |
| `idx_chapters_work_type` | `work_id, chapter_type` | 查询作品下指定章节类型。 |
| `fk_chapters_work_id` | `work_id -> works.id` | 章节归属作品。 |

### 4.3 `chapter_outlines` 章节大纲表

作用：

- 保存正式章节大纲。
- 一章最多一条当前正式大纲。
- 支撑大纲读取、手工保存、候选确认和生成正文。
- `revision` 与 `version` 共同用于手工保存和候选确认的条件更新。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 ID。 |
| `work_id` | `BIGINT` | 所属作品 ID，关联 `works.id`。 |
| `chapter_id` | `BIGINT` | 所属章节 ID，关联 `chapters.id`。 |
| `confirmed_brief_id` | `BIGINT` | 当前大纲绑定的已确认 Brief ID，关联 `chapter_briefs.id`。 |
| `outline_status` | `VARCHAR(32)` | 大纲状态：`draft` 草稿，`confirmed` 已确认，`outdated` 已过期。 |
| `outline_content` | `JSON` | 大纲内容，包含本章目标、场景、人物变化、节奏、约束和未决问题。 |
| `revision` | `INT` | 大纲修订版本号，用于乐观锁。 |
| `deleted` | `TINYINT` | 是否删除。 |
| `version` | `INT` | 实体通用乐观锁版本，供 MyBatis-Plus 通用映射和条件更新使用。 |
| `gmt_create` | `DATETIME` | 创建时间。 |
| `gmt_modified` | `DATETIME` | 更新时间。 |

索引与约束：

| 名称 | 字段 | 作用 |
| --- | --- | --- |
| `uk_chapter_outlines_chapter_id` | `chapter_id` | 保证一章只有一条正式大纲。 |
| `idx_chapter_outlines_work_gmt_modified` | `work_id, gmt_modified` | 按作品查询最近更新的大纲。 |
| `idx_chapter_outlines_status_gmt_modified` | `outline_status, gmt_modified` | 按状态查询大纲。 |
| `fk_chapter_outlines_work_id` | `work_id -> works.id` | 大纲归属作品。 |
| `fk_chapter_outlines_chapter_id` | `chapter_id -> chapters.id` | 大纲归属章节。 |
| `idx_chapter_outlines_confirmed_brief_id` | `confirmed_brief_id` | 查询绑定某个已确认 Brief 的大纲。 |
| `fk_chapter_outlines_confirmed_brief_id` | `confirmed_brief_id -> chapter_briefs.id` | 固化大纲实际承接的章节共识。 |

### 4.3.1 `chapter_outline_candidates` 章节大纲调整候选表

作用：

- 保存异步生成但尚未确认落版的大纲调整候选。
- 固化候选提交时的会话、已确认 Brief 和正式大纲 `id/revision/content` 快照。
- 保存结构化候选内容、确定性差异、三维共识影响与确认后的正式大纲引用。
- 候选状态仅为 `queued`、`running`、`ready`、`failed`、`canceled`、`abandoned`、`confirmed`；候选本身不替代正式大纲。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 ID。 |
| `work_id` / `chapter_id` | `BIGINT` | 所属作品和章节。 |
| `conversation_id` | `BIGINT` | 提交时验证过归属的章节会话。 |
| `ai_task_id` | `BIGINT` | 唯一关联的异步任务。 |
| `confirmed_brief_id` | `BIGINT` | 候选绑定的 latest confirmed Brief。 |
| `base_outline_id` / `base_outline_revision` | `BIGINT` / `INT` | 候选生成时的正式大纲身份和业务修订。 |
| `base_outline_content` | `JSON` | 不随正式大纲后续编辑变化的基础内容快照。 |
| `candidate_status` | `VARCHAR(32)` | 候选生命周期状态。 |
| `adjustment_instruction` | `VARCHAR(2000)` | 用户调整要求。 |
| `candidate_content` | `JSON` | Provider 返回并经校验的结构化候选内容。 |
| `diff_json` | `JSON` | 按 scene ID 计算的目标、冲突、约束和场景增删改移差异。 |
| `consensus_impact_json` | `JSON` | 相对绑定 Brief 的三维共识影响。 |
| `result_outline_id` / `result_outline_revision` | `BIGINT` / `INT` | 确认成功后指向正式大纲版本；未确认时为空。 |
| `deleted` / `version` | `TINYINT` / `INT` | 软删除和候选状态条件更新版本。 |
| `gmt_create` / `gmt_modified` | `DATETIME` | 创建和最近修改时间。 |

索引与约束：

| 名称 | 字段 | 作用 |
| --- | --- | --- |
| `uk_chapter_outline_candidates_ai_task_id` | `ai_task_id` | 一个 AI 任务仅对应一个候选。 |
| `idx_outline_candidates_chapter_id` | `chapter_id, id` | 查询章节最新候选。 |
| `idx_outline_candidates_brief_id` | `confirmed_brief_id` | 按 Brief 追溯候选。 |
| 外键 | `work_id/chapter_id/conversation_id/ai_task_id/confirmed_brief_id/base_outline_id/result_outline_id` | 保障候选关联资源存在。 |

`outline_content` 结构示例：

```json
{
  "goal": "隐藏房间回应林风，姚宁第一次改写自己的判断。",
  "coreConflict": "姚宁不愿承认隐藏房间回应，但事实开始逼近她。",
  "scenes": [
    {
      "id": "scene_1",
      "title": "怀表出现反应",
      "content": "林风靠近隐藏房间时，怀表先出现细微变化。",
      "tags": ["增加悬念"]
    }
  ],
  "characterChange": "姚宁从怀疑变成动摇。",
  "emotionPace": "克制疑惑 -> 紧张确认 -> 关系松动",
  "constraints": ["姚宁不能突然完全信任", "不要提前解释隐藏房间规则"],
  "openQuestions": ["姚宁是否当场追问林风？"]
}
```

作用：

- 保存章节共创会话和章节编辑 AI 会话。

字段：

| `chapter_id` | `BIGINT` | 所属章节 ID，关联 `chapters.id`。 |
| `conversation_type` | `VARCHAR(32)` | 会话类型：`chapter_co_creation` 章节共创，`chapter_editing` 章节编辑。 |
| `conversation_status` | `VARCHAR(32)` | 会话状态，默认 `active`。 |
| `deleted` | `TINYINT` | 是否删除。 |
| `version` | `INT` | 乐观锁版本号。 |
| `gmt_create` | `DATETIME` | 创建时间。 |
| `gmt_modified` | `DATETIME` | 更新时间。 |

索引与约束：

| 名称 | 字段 | 作用 |
| --- | --- | --- |
| `idx_chapter_conversations_chapter_status` | `chapter_id, conversation_status` | 查询章节下有效会话。 |
| `idx_chapter_conversations_work_gmt_modified` | `work_id, gmt_modified` | 查询作品下最近更新会话。 |

- 支持章节共创和编辑页 AI 对话复用。

字段：

| 字段 | 类型 | 说明 |

| `conversation_id` | `BIGINT` | 所属会话 ID，关联 `chapter_conversations.id`。 |
| `chapter_id` | `BIGINT` | 所属章节 ID，关联 `chapters.id`。 |
| `message_role` | `VARCHAR(32)` | 消息角色：`user` 用户，`assistant` 助手，`system` 系统。 |
| `content` | `LONGTEXT` | 消息正文。 |
| `ai_task_id` | `BIGINT` | 关联 AI 任务 ID，可为空。 |
| `focus_brief_id` | `BIGINT` | 用户消息对焦的 draft Brief ID，可为空。 |
| `focus_decision_key` | `VARCHAR(64)` | 用户消息对焦的待决键，与 `focus_brief_id` 成对为空或非空。 |
| `deleted` | `TINYINT` | 是否删除。 |
| `version` | `INT` | 乐观锁版本号。 |
| `gmt_create` | `DATETIME` | 创建时间。 |
| `gmt_modified` | `DATETIME` | 更新时间。 |

索引与约束：

| 名称 | 字段 | 作用 |
| --- | --- | --- |
| `idx_ccm_conversation_gmt_create` | `conversation_id, gmt_create` | 按会话时间线读取消息。 |
| `idx_ccm_chapter_gmt_create` | `chapter_id, gmt_create` | 按章节读取消息历史。 |
| `idx_ccm_ai_task_id` | `ai_task_id` | 查询任务关联消息。 |
| `fk_ccm_conversation_id` | `conversation_id -> chapter_conversations.id` | 消息归属会话。 |
| `fk_ccm_chapter_id` | `chapter_id -> chapters.id` | 消息归属章节。 |
| `fk_ccm_ai_task_id` | `ai_task_id -> ai_tasks.id` | 消息关联任务。 |
| `idx_ccm_focus_brief_id` | `focus_brief_id` | 查询对焦某个 Brief 的讨论消息。 |
| `fk_ccm_focus_brief_id` | `focus_brief_id -> chapter_briefs.id` | 对焦引用必须指向真实 Brief。 |
| `chk_ccm_focus_pair` | `focus_brief_id, focus_decision_key` | 两个对焦字段必须同时为空或同时非空。 |

### 4.6 `chapter_briefs` 章节共创收束摘要表

作用：

- 保存 AI 或会话讨论过程中整理出来的结构化共识草稿和确认历史。
- 不保存正式章节大纲。
- 正式章节大纲由 `chapter_outlines` 保存。

典型内容：

- 本章任务、状态变化、关键推进和读者进展。
- 写作边界。
- 具有稳定 key、状态和来源消息 ID 的待决列表。
- 无法识别为结构化 V1 的历史自由文本。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT` | 主键 ID。 |
| `work_id` | `BIGINT` | 所属作品 ID，关联 `works.id`。 |
| `chapter_id` | `BIGINT` | 所属章节 ID，关联 `chapters.id`。 |

## 八、读取与写入要点

- 首页和作品概览中的章节数量、字数等统计，当前不在主表冗余保存，可查询或后续统计表补齐。
- 保存章节正文时使用 `chapters.version` 做冲突控制。
- 保存章节大纲时使用 `chapter_outlines.revision` 做冲突控制。
- 生成正文时应记录 `outline_id`、`outline_revision` 和 `basis_snapshot_json`。
- `chapter_briefs` 保存共识草稿与确认历史，不作为正式大纲；只有 `confirmed` 可供大纲和正文生成消费。
- 用户配置统一从 `user_configs` 按 `user_id + config_key + deleted=0` 读取。
- 模型 API Key 只从 `llm_credentials` 读取；`user_configs.config_value` 不得包含明文、密文或 nonce。
- 导入既有小说时，章节正文仍写入 `chapters.content`；献词、序幕、正文和尾声用 `chapters.chapter_type` 区分。
- 作品级人物、地点、组织、规则、物品等长期资料写入 `setting_entries`，进入正式设定前可先写入 `setting_candidates`。
- 伏笔、线索和待回收内容写入 `foreshadowing_items`，通过来源章节与回收章节追踪叙事闭环。
- 长篇上下文检索优先使用 `chapter_summaries` 和 `chapter_key_events`，避免每次 AI 调用直接拼接整本正文。
### `story_context_snapshots` 故事上下文快照

- V10 新增不可变故事上下文快照，按 `scope_key + content_hash` 幂等复用，并用 `snapshot_version` 记录同一作用域的内容演进。
- `snapshot_json` 保存选中上下文项和未选中项的原因；`context_window_tokens`、`output_reserve_tokens`、`input_budget_tokens` 和 `estimated_input_tokens` 用于复盘预算。
- 快照通过 `work_id`、`chapter_id`、`conversation_id` 约束数据归属；`ai_tasks.context_snapshot_id` 保存异步章节讨论任务实际使用的快照。
- V1 的快照是内部服务数据，不提供独立 HTTP 接口；作品简介、多用户所有权和 Agent Run 关联属于后续能力。
