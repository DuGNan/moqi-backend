# 正文知识提取接口

## 适用范围

本契约用于从用户已经采纳的章节正文，或已进入待发布链路的不可变正文 revision 中，提取章节摘要、关键事件、作品设定和伏笔候选。自动流程只创建候选。generation 兼容路径在作者确认后写入正式知识；待发布 revision 路径只保存作者决策，随 Story Release 发布事务原子生效。

正文采纳事务提交后，服务端会幂等创建 `story_knowledge_extraction_v1` Agent Run。提取入队或后续 Provider 失败不会回滚已经采纳的正文。

## 批次状态

批次状态为 `queued`、`running`、`ready`、`failed`、`stale`、`canceled`、`timed_out`。同一已采纳 generation，或同一不可变 prose revision、Story Release 基线与 extractor 版本分别只创建一个批次；相同来源重复请求返回原批次，来源不同则返回 `AGENT_RUN_IDEMPOTENCY_CONFLICT`。同一 revision 被重新放入新基线工作区时可以创建新批次，发布门禁只读取与工作区基线一致的批次。

批次固化 `generationId`、`sourceProseRevisionId`、`sourceStoryReleaseId`、正文指纹和提取器版本。generation 与 revision 查询接口相互隔离，不能凭共享的 generation ID 跨来源读取或操作批次。generation 路径检查当前已采纳正文；revision 路径检查不可变正文哈希和创建时的 Story Release 基线。Provider 调用前、结果校验、重试和候选人工处理前都会重新检查来源；候选处理会按 work、revision 顺序锁定并复核，避免与发布、回退或放弃 revision 并发越过基线。来源变化时批次进入 `stale`，候选不能写入正式知识层；取消仍允许清理已经过期的运行任务。

候选类型为：

- `chapter_summary`
- `key_event`
- `setting`
- `foreshadowing`

候选状态为 `pending`、`conflict`、`duplicate`、`confirmed`、`ignored`。`duplicate` 只能忽略；`conflict` 必须显式选择 `merge` 或 `replace`。确认和忽略均通过候选 `baseVersion` 做乐观锁保护。跨 Story Release 基线的旧非终态候选不参与新批次指纹去重，避免旧候选已不可处理而新候选又被误判重复。

## API

### 创建或复用提取批次

`POST /api/chapters/{chapterId}/generations/{generationId}/knowledge-extractions`

```json
{
  "idempotencyKey": "client-generated-key"
}
```

只有属于当前章节且状态为 `accepted` 的 generation 可以创建批次。

待发布 revision 使用以下接口创建或恢复批次：

- `POST /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/knowledge-extractions`
- `GET /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/knowledge-extractions/latest`
- `GET /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/knowledge-extractions/{batchId}`

只有归属匹配、内容哈希有效、拥有可追溯 generation 且状态为 `confirmable` 的 revision 可以新建批次；读取已存在批次不要求 revision 仍处于待发布状态。

### 查询批次

- `GET /api/chapters/{chapterId}/generations/{generationId}/knowledge-extractions/latest`
- `GET /api/chapters/{chapterId}/generations/{generationId}/knowledge-extractions/{batchId}`

响应包含安全来源指纹、批次状态、提取器版本、候选以及 `currentAttempt`、`retryable`。只有批次为 `failed`，关联 Run 的工作流、作品、章节和 AI Task 归属完全匹配，最新失败步骤正是 `extract`，Runtime 持久化步骤仍允许重试，且冻结的 generation 或 prose revision 来源仍有效时，才返回 `retryable=true`；其他状态安全关闭。`currentAttempt` 只在失败批次中返回最新 `extract` attempt。不会返回 Prompt、隐藏推理或 Provider 凭据。

### 重试与取消

- `POST .../knowledge-extractions/{batchId}/retry`

```json
{
  "expectedAttempt": 2
}
```

- `POST .../knowledge-extractions/{batchId}/cancel`

客户端必须先读取批次并原样提交当前 `currentAttempt`。服务端先复核来源、Runtime 归属、步骤重试资格和 attempt，再以批次 `version + failed` 条件把业务状态 CAS 为 `running`，随后复用原 Run 重试 `extract`；旧 attempt、重复点击或状态竞争统一返回冲突，不创建新 Run。业务状态推进与 Runtime 重试处于同一事务，调用失败会回滚；重试继续复用原批次和冻结来源，不重新拼装正文输入。

### 确认候选

`POST /api/knowledge-extraction-candidates/{candidateId}/confirm`

```json
{
  "baseVersion": 0,
  "resolution": "create",
  "mergeTargetId": null,
  "resolvedPayload": null
}
```

`resolvedPayload` 允许用户在确认前编辑候选。服务端会重新执行 Schema、作品归属、引用类型和跨作品校验。`conflict` 候选不能使用 `create`。

revision 候选确认后返回 `candidateStatus=confirmed`，但 `targetId/targetType` 在发布前为空（统一 NON_NULL 序列化会省略它们）；它表示作者已处理候选，不表示正式知识已切换。数据库冻结决策方式、编辑后的 payload、目标 ID 与目标版本。重复确认返回原结果；并发请求可能返回冲突，客户端重新读取后复用已确认结果，不重新创建候选。

发布只应用变更 revision 在精确基线下最新 ready 批次的已确认决策；四类正式知识写入、目标绑定、知识来源映射、正文指针与 release 切换共享事务。目标被其他操作修改时拒绝发布并整体回滚，不能静默覆盖作者后续维护。当前接口不支持改写已确认决策；这类冲突需在新 revision / 基线工作区重新处理知识，不得把重复确认当作强制覆盖入口。

### 查询发布版本知识

`GET /api/works/{workId}/story-revisions/releases/{releaseId}/knowledge`

返回 `releaseId` 和 `items`；每项包含 `type`、知识 `id`、`content`。content 使用对应知识的业务属性名，JSON 类业务列保留字符串形式；不返回持久化版本、删除标记、审计时间或作品 ID。当前 release 读取有效知识投影，包含作者正常维护；历史 release 读取完整内容快照，不解析为当前表中的新内容。跨作品读取、缺失可靠历史快照返回冲突，完整空快照返回空集合。

新 release 保存初始快照；离开当前状态时封存最后有效内容，历史封存后不可覆盖。回退创建新 release，并恢复四类知识的内容和显式空字段，当前多余记录只软删除。V56 前已离开的历史 release 无法自动重建可靠快照，拒绝回退；迁移前已经提前写入的知识也不会被猜测还原。

### 忽略候选

`POST /api/knowledge-extraction-candidates/{candidateId}/ignore`

```json
{
  "baseVersion": 0
}
```

## 安全与权威边界

- Agent Run 输入只保存批次、作品、章节、generation、AI Task 和来源指纹等安全引用。
- Provider 输出必须使用 `schemaVersion=1`，顶层、候选、payload 与 evidence 都使用精确字段集合，整数不能由字符串或小数强制转换；Provider 只允许生成 `seed` 伏笔候选。每个候选必须提供正文证据的 Java UTF-16 offset 和原文。offset 不准确时只允许按冻结正文中唯一逐字出现的证据文本有界重算；缺失或重复匹配仍使整批失败。
- 发布新 Story Release 时，未变 revision 的知识来源从上一 release 复制；发生变化的 revision 只消费与上一 release 基线一致、门禁选中的最新 ready 批次，旧基线或旧提取器批次不会混入新快照。
- 非法 JSON、非法证据、跨作品引用和未知枚举均使工作流失败，不伪装成可确认候选。
- 自动流程不修改 `setting_entries`、`foreshadowing_items`、`chapter_summaries`、`chapter_key_events` 或 `chapters.content`。
- 完整真实 Provider、数据库和 UI 人工闭环由 Issue #81 统一验收。
