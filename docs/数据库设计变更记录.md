# 数据库设计变更记录

这份文档记录数据库设计和 Flyway 迁移的演进历史。当前库结构请看：

- `docs/2026-06-09-数据库设计.md`

---

## 2026-07-30

- 增加 `V14__add_agent_runtime_foundation.sql`。
- 新增 `agent_runs`、`agent_run_steps`、`agent_checkpoints` 和 `agent_interruptions`，分别持久化框架无关的运行状态、步骤尝试、稳定 JSON checkpoint 与人工恢复令牌哈希；Run 使用用户、工作流和幂等键唯一约束，checkpoint 使用 Run 内单调 sequence，恢复、取消与终态更新均依赖状态和版本条件。
- `ai_tasks` 保持粗粒度异步任务入口，Agent Run 通过可选 `ai_task_id` 关联；等待人工确认期间任务保持 running，Run 终态同步为任务终态。

- 增加 `V13__add_outline_adjustment_candidates.sql`。
- 新增 `chapter_outline_candidates`，持久化大纲调整候选的任务绑定、会话与已确认 Brief、基础大纲快照、结构化结果、确定性差异、共识影响、状态和确认结果。
- `ai_tasks` 新增 `result_outline_candidate_id`，使候选任务可在页面刷新后从 AI 任务恢复候选资源引用。
- 正式大纲的手工保存与候选确认均以 `id + revision + version + deleted` 条件更新，避免并发写入相互覆盖。

## 2026-07-29

- 增加 `V12__add_chapter_outline_version.sql`。
- `chapter_outlines` 补充 `version` 通用乐观锁列，使数据库结构与继承 `BaseEntity` 的 MyBatis-Plus 实体映射保持一致，避免 Story Context Engine 查询正式大纲时生成不存在字段的 SQL。

## 2026-07-28

- 增加 `V10__add_story_context_snapshots.sql`，持久化确定性上下文选择结果，并通过 `ai_tasks.context_snapshot_id` 追溯任务实际输入。
- 增加 `V11__add_chapter_consensus_references.sql`。
- `ai_tasks` 新增 `task_input_json` 与 `result_brief_id`，支持章节共识任务断线恢复和结果追溯。
- `chapter_conversation_messages` 新增成对的 `focus_brief_id/focus_decision_key`，只持久化讨论对焦引用。
- `chapter_outlines` 新增 `confirmed_brief_id`，固定大纲承接的已确认章节共识。

## 2026-07-27

- 增加 `V9__add_llm_credentials.sql`。
- 新增 `llm_credentials`，保存按用户、供应商和凭据类型隔离的 AES-GCM 密文、随机 nonce、keyId 与安全摘要。
- `model.active` 继续保存非敏感模型配置；旧明文 API Key 由应用启动迁移在同一事务内写入凭据表并从配置 JSON 清除。

## 2026-07-05

- 增加 `V8__add_story_knowledge_layer_tables.sql`。
- 为 `chapters` 增加 `chapter_type`，用于区分献词、序幕、正文、尾声和其他章节块。
- 新增 `setting_candidates`、`setting_entries`、`foreshadowing_items`、`chapter_summaries`、`chapter_key_events`，作为长篇小说知识层的第一批最小表结构。
- 新增长篇小说导入与验证脚本，用《龙族Ⅰ-火之晨曦》验证章节正文可完整还原，并验证设定、伏笔、章节摘要、关键事件可结构化存储。

## 2026-07-05

- 当前 P0 数据库统一使用自增 `id` 作为主键和关联键。
