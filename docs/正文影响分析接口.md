# 正文影响分析接口

## 适用范围

正文影响报告比较同一章节的固定基线 revision 与待发布 revision。报告是发布前的只读分析候选，不确认事实、不修改正文，也不写入规划或知识权威态。

## 接口

- `POST /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/impact-reports`：创建或按 `idempotencyKey` 复用报告。带工作区时从 `workspace.baselineReleaseId` 的章节映射解析 baseline；不带工作区时从作品当前 Story Release 解析。请求中的 `baselineRevisionId` 只能用于一致性校验，不能指定任意 parent。
- `GET /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/impact-reports/latest`：读取 revision 最新报告。
- `GET /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/impact-reports/{reportId}`：读取报告、事实变化、受影响资产和 Agent Run/模型调用引用；路径中的作品、章节和 revision 必须全部与报告一致。
- `POST /api/works/{workId}/story-revisions/chapters/{chapterId}/revisions/{revisionId}/impact-reports/{reportId}/retry`：按失败步骤 `expectedAttempt` 重试；路径身份不匹配时拒绝，不会恢复其他 revision 的 Agent Run。
- `GET /api/works/{workId}/story-revisions/workspaces/{workspaceId}`：`impactSummary` 返回报告总数、ready/blocking/failed/stale 数量、报告 ID、影响范围及结构化 `blockingItems`。

## 状态与门禁

持久化运行状态为 `queued/running/ready/failed`；读取时若正文哈希、baseline Story Release/revision、分析器版本或作品来源图指纹发生变化，以 `stale` 返回并阻塞旧结论复用。来源图指纹确定性覆盖当前作品全部未删除的 V24 不可变 source snapshot 及其中来源边，因此其他章节引用变化也会使旧报告失效。`prose-impact-analyzer-v2` 要求证据文本逐字来自目标正文，offset 使用 Java String 的 UTF-16 下标；仅当证据文本在目标正文中唯一精确出现时，服务端可重算错误或缺失的 offset。证据不存在、出现多次且原 offset 无法定位，或需要裁剪、模糊匹配时，报告以 `impact_output_invalid_reference`、`impact_output_ambiguous_reference` 等安全类别失败，Agent Step 只记录 `changes[i].evidence*` 字段路径，不回显正文。每条事实还必须返回 `affectedChapterIds`。`local` 只能指向当前章，`adjacent` 只能指向当前章及相邻章，`cross_chapter` 必须明确列出当前作品中的真实引用章节且不能退化为全书传播。`work`、`unknown` 或 `faction_rule` 一律进入 needs-human 阻塞，不自动传播全文。`none/language_only` 不产生事实或知识失效，只完成当前章表达检查。角色主张、传闻、推测、未解释现象和作者后台信息始终保留其非权威认知属性。

`none/language_only` 之外的 ready 报告还必须等待目标 prose revision 最新知识提取批次进入 `ready`，且该批次全部知识候选由用户处理为 `confirmed/ignored`。`pending/conflict/duplicate/queued/running/failed/stale` 均阻塞，不会自动确认。相同 release 中多个 confirmed candidate 指向同一知识目标时，发布映射按知识类型和 ID 去重，确定性保留最小 candidate ID；其他候选和证据仍保留在知识批次中。

只有 Story Release 发布或回退事务会激活来源传播：按影响范围向 V24 validity audit 写入幂等事件，并原子切换 release 对应的已确认知识来源映射。报告创建和重试本身不会触发传播。
