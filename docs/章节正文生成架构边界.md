# 章节正文生成架构边界

## 适用范围

本文记录正式章节正文候选的生成链路与内部职责边界，包括容量评估、软篇幅策略以及只读 Brief/实体卡预览接口；所有模型结果仍保持候选语义，只有用户采纳才会修改权威正文。

## 当前调用链

1. `SceneGenerationController` 接收创建、查询、取消、重试和重新生成请求。
2. `ChapterCapacityAssessmentServiceImpl` 在生成前冻结 Brief、已发布场景与目标篇幅；`ChapterCapacityAssessmentWorkflowDefinition` 依次执行确定性预检、Provider V2 结构化判断和收束，Provider 失败或非法输出保存带降级原因的确定性候选。`SceneGenerationServiceImpl` 校验已发布规划、来源、幂等键、容量门禁和模型配置版本，把结构化 Brief、容量结果、来源指纹与作者决定随 `basisSnapshotJson` 冻结，再创建生成资源。模型调用不在数据库事务中。
3. Agent Runtime 以 `load_generation -> generate_scene:{sceneKey} -> cohere_chapter -> finalize_generation` 顺序领取步骤，并持久化 attempt、effect key 与 checkpoint。历史 `scene_join_legacy` 批次仍按原读取和最终拼接规则处理。
4. `SceneNovelGenerationWorkflowDefinition` 只分派步骤并协调状态迁移；业务细节由下列内部组件承担。
5. `ChapterGenerationBriefSourceLoader` 只读取同作品、当前有效、已确认或已发布的固定来源；`chapter.entitycard` 按显式 ID、唯一名称或别名、章节文本和上章状态选择正式实体并提供安全歧义降级；`ChapterGenerationBriefCompiler`、`ChapterGenerationBriefRenderer` 与 `ChapterGenerationBriefFingerprint` 将这些来源编译为带优先级的自然语言和稳定 SHA-256 指纹。`ChapterGenerationPromptCompiler` 只读取批次冻结的 Brief 并创建或复用 Story Context Snapshot，重试和恢复不重新选择来源；`scene-novel-v4` 正文模型不接收原始 ScenePlan JSON。
6. `ChapterGenerationModelInvoker` 校验批次固定的配置描述，创建 Observed Provider，传播取消请求并校验流式终态。场景与整章只接收软篇幅提示，偏离区间不会触发自动扩写、压缩或失败。
7. `ChapterGenerationStateStore` 集中查询 generation/scene，以版本条件更新场景、收束结果、失败状态和最终 `preview` 候选。
8. `ChapterGenerationCompletionHandler` 发布不含正文和 Prompt 的资源事件。正文评价与有界修订目前仍由独立评价 API/Workflow 显式创建，不在生成完成后自动触发。
9. 用户明确采纳候选后，既有服务才以 `chapters.version` 条件写入权威正文并触发后续知识提取；生成完成本身不提升候选的权威等级。

## 状态、事务与恢复边界

| 关注点 | 当前边界 |
| --- | --- |
| 状态 | generation 由 `queued` 进入 `running`，完成后进入 `preview`；scene 由 `pending/failed` 进入 `running`，成功后为 `completed`；复制场景保持 `copied`；收束使用独立 `cohesion_status`。 |
| 事务 | 创建批次、步骤结果应用、失败记录和最终采纳分别使用短数据库事务；远程 Provider 调用不持有数据库事务。 |
| 幂等 | 创建接口使用章节范围幂等键；Agent Runtime 使用 step/effect key 与 attempt；状态写入使用版本或预期状态条件避免重复副作用。 |
| checkpoint | Agent Runtime 保存下一步骤和 `lastSceneId`；已为 `completed/copied` 的场景在恢复时跳过模型调用。 |
| 取消 | AI Task/Agent Run 取消传播到 `AgentRunCallRegistry`，活动 `LlmStreamCall` 收到取消；取消后的增量不再追加。 |
| 来源版本 | 容量评估固定 Brief、规划、目标篇幅和输入指纹；生成批次再固定容量结论、作者决定、安全模型配置与其他来源，上游变化不静默改写运行中批次。 |
| Snapshot | scene 已有关联 Snapshot 时直接复用；首次生成才构建并以版本条件绑定，重试不重新选择故事事实。 |
| 模型观测 | 场景和整章收束分别使用稳定 logical call ID、模板版本和来源指纹；物理重试由 Provider 观测层记录 attempt。 |
| 候选确认 | scene 稿和 `chapter_generations.generated_content` 都是候选；只有用户采纳才写入 `chapters.content`。 |
| 评价/修订 | `GenerationEvaluationWorkflowDefinition` 是独立显式流程；生成完成事件当前不自动创建评价报告或修订候选。 |

## 内部职责与后续接入点

- `ChapterGenerationBriefService` 是生成批次、`GET /api/chapters/{chapterId}/generation-brief-preview` 和 `GET /api/chapters/{chapterId}/generation-entity-cards-preview` 共用的来源校验入口；两个预览都只读、不调用模型、不持久化 Brief 或实体卡。`ChapterGenerationPromptCompiler` 是运行期消费冻结 Brief 的唯一入口。
- `ChapterCapacityCompiler` 负责确定性容量基线与稳定指纹，`ChapterCapacityAssessmentServiceImpl` 负责持久化、恢复和生成门禁；两者都只消费 Brief 服务，不修改 Brief 契约。
- `ChapterGenerationLengthPolicy` 只提供篇幅预设、整章软区间与 Provider 输出安全上限；历史隔离实验仍保留自身兼容策略，不影响正式生成链路。
- `ChapterGenerationModelInvoker` 隔离 Provider、观测和流式终态，不负责容量判断或持久化。
- `ChapterGenerationStateStore` 隔离 MyBatis 查询与 CAS 状态写入，不发起模型调用。
- `ChapterGenerationStepPlanner` 保持逐场景顺序和历史整章收束步骤选择，为 #96 新版整章主链提供可替换的确定性规划点。
- `ChapterGenerationCompletionHandler` 是后续 #105/#106 评价与有界修订触发的接入点；当前只发布既有事件，避免本 Issue 偷渡自动评价语义。

## 前端审视结论

最新前端 `origin/main` 中，`GenerationPreviewPage` 集中组合 `generationStatus`、`contentAssemblyMode` 与 `cohesionStatus`；API adapter 只负责解析和兼容默认值，未发现两个及以上组件重复判断同一状态组合。因此 #102 不创建前端分支，也不引入 `deriveGenerationPresentationState`。风险是未来第二个页面或组件开始复制该组合判断时，应立即抽取纯领域投影并补测试。

## 不在当前范围

- 不修改页面文案、交互或前端路由；后端只增加容量评估与结构化实体卡相关接口。
- 容量评估使用 V35 持久化；实体卡从既有正式设定确定性编译，不新增持久化设施。
- 正文 Prompt 只接收软篇幅与叙事权重；实体卡只扩展 Brief 的相关实体说明，不改变候选采纳规则。
- 不自动触发评价、修订或知识确认。
- 不删除无法由自动化测试证明无调用方的历史兼容逻辑。
