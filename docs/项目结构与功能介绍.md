# 墨契后端项目结构与功能介绍

## 文档目的

这份文档用于帮助新会话、新协作者或未来回看代码的人快速理解后端项目当前的结构、功能和运行约束。
它不是一次性说明，而是随着模块、接口、数据结构和运行约束演进持续补充的后端项目介绍文档。

## 维护规则

1. 默认在每次 `commit` 前检查这份文档是否需要更新。
2. 如果本次改动改变了模块边界、服务职责、接口行为、数据库结构、脚本使用方式、运行依赖或关键配置约束，应同步补充。
3. 如果只是极小的无语义调整，且不会影响后续会话理解项目，可以不更新。
4. 优先记录高价值信息，不必机械罗列所有实现细节。

## 当前项目定位

- Moqi 后端当前承担写作主流程的数据与服务基础：作品、章节、章节共创、章节大纲/简报、章节生成、章节正文保存，以及长篇小说第一版必通知识层。
- 当前接口文档生成应以 P0 写作主流程和已落库知识层为准，不为尚未落库的增强能力生成正式接口。

## 当前模块与分层概览

- `moqi-start` 是 Spring Boot 启动模块，负责装配配置、扫描组件并承载 Flyway 迁移资源。
- `moqi-web` 是 Web 接入层，包含健康检查、作品章节、章节共创、知识层、用户配置、模型状态和 AI 任务 Controller，以及全局异常处理。
- `moqi-service` 是业务服务层，承载应用服务和领域流程编排。
- `moqi-dal` 是数据访问层，包含 MyBatis-Plus 实体与 Mapper；当前已有作品、章节、章节共创、章节生成和知识层相关实体。
- `moqi-dal` 的持久化实体统一使用 Lombok `@Data` 生成机械方法，不重复声明 `@Getter`、`@Setter`。Lombok 仅作为编译期依赖，不参与运行时逻辑。
- `moqi-common` 是公共基础模块，包含统一响应、错误码和业务异常等跨模块基础类型。
- 所有生产与测试 Java 顶层类型均在 import 区域之后、类型级注解和声明之前维护作者、创建日期和职责说明；具体模板与填写规则以仓库根目录 `AGENTS.md` 为准。

## 构建与规范检查

- 后端使用多模块 Maven 构建，提交前执行 `mvn clean verify` 和 `git diff --check`。
- 根 `pom.xml` 在 Maven `verify` 阶段为各 Java 模块执行 Alibaba P3C PMD 检查，检查结果写入各模块的 `target/pmd.xml`。
- P3C 当前采用报告模式，`failOnViolation=false`；规范违规会出现在 Maven 日志和报告中，但不会因此阻断编译、测试、验证或打包。
- Maven `BUILD SUCCESS` 仅表示构建和测试成功，不表示 P3C 无违规；交付时必须分别报告 Maven 结果、P3C 结果和遗留规范问题。

## 主要功能与服务说明

- 作品与章节能力：保存作品基础信息、章节标题、章节顺序、章节类型、正文和工作流状态。
- 章节共创能力：提供章节活动会话创建/查询、会话消息列表/发送、章节 brief 读取/保存接口；消息发送可按请求创建 `ai_tasks` 排队记录，但不接入真实 LLM 回复。
- 章节大纲与生成能力：`chapter_outlines` 保存正式章节大纲，当前提供读取、保存和刷新草稿接口，并使用 `revision/baseRevision` 做乐观锁冲突控制；`chapter_generations` 完整保存大纲 ID/revision、生成模式、长度参数、依据快照、生成正文、字数和 AI 任务 ID，支持预览查询、采纳、拒绝和基于原依据重新生成。
- 章节正文能力：提供章节正文读取和条件保存接口；手工保存与生成稿采纳都使用 `chapters.version` 条件更新，冲突时返回服务端正文、版本与保存时间。
- 长篇知识层能力：按作品筛选候选设定和正式设定，确认候选时先通过 `SELECT ... FOR UPDATE` 锁定候选父行，再在同一事务内创建或合并正式设定并更新候选状态，避免外键子表插入后的父行锁升级竞争；候选确认和忽略使用 `pending` 状态、版本及软删除条件做原子更新，合并正式设定同样检查版本和软删除状态；候选、正式设定和伏笔列表支持可选 `page/pageSize`，默认第 `1` 页、每页 `50` 条、上限 `100` 条，并按更新时间和 ID 倒序稳定分页；支持幂等忽略、伏笔创建、章节摘要和关键事件读取。
- 用户配置能力：当前用户固定为 `local-user`，只开放 `model.active`、`writing.preferences`、`appearance.preferences`、`sync.preferences` 四类配置，并使用 `baseVersion/version` 做乐观锁控制。缺失配置读取返回版本 `0` 和空对象，客户端可基于版本 `0` 创建，创建成功后的持久化版本为 `1`；并发创建触发唯一键竞争时返回 `CONFIG_VERSION_CONFLICT`。
- 配置安全边界：配置保存会递归拒绝 `apiKey`、`accessKey`、`privateKey`、`token/tokens`、`secret`、`clientSecrets`、`password`、`credential` 等明文敏感键，读取历史数据时也会递归移除同类字段；`maxTokens` 仅以正整数形式作为明确白名单数值字段保存，`apiKeyMasked` 等脱敏摘要必须是包含至少四个连续星号、且首尾最多各暴露四个字母或数字的字符串，非法 masked 明文、对象和数组在保存时拒绝、历史读取时移除；当前不保存、不返回明文密钥，也不提供加密或密钥存储能力。
- 模型状态能力：只根据 `model.active` 的 provider、providerName、baseUrl、defaultModel 元数据判断是否已配置，不发起网络请求；已配置模型仍返回 `available=false`、`lastTestStatus=not_tested`。
- AI 任务能力：提供 `ai_tasks` 查询与幂等取消，只接受 `queued`、`running`、`succeeded`、`failed`、`canceled` 五种状态；非终态取消发生版本竞争时会在 `READ_COMMITTED` 事务中重读最新版本并最多尝试三次，竞争耗尽返回 `AI_TASK_STATE_CONFLICT`，终态取消保持当前状态。本能力不负责创建任务。

## 接口与数据流

- 当前已实现接口覆盖：作品章节、章节共创会话、会话消息、章节 brief、章节大纲读取/保存/刷新草稿、章节生成创建/详情/最近预览/采纳/拒绝/重新生成、章节正文读取/保存，以及设定候选查询/确认/忽略、正式设定查询、伏笔查询/创建、章节摘要、关键事件、用户配置、模型状态、AI 任务查询/取消。
- 章节生成创建接口同步返回 `draft` 资源标识，本地生成完成后生成记录进入 `preview`、关联 `ai_tasks` 进入 `succeeded`；生成器通过 `ChapterContentGenerator` 接口隔离，当前实现根据章节标题、brief、大纲快照和生成参数确定性构造中文预览，不调用真实 LLM。
- 创建和重新生成响应中的 `gmtCreate` 以生成记录持久化后的重新查询结果为准，不依赖数据库默认时间自动回填到插入实体；最近预览查询在数据库侧按创建时间和 ID 倒序并 `LIMIT 1`，且只读取预览摘要字段。
- 生成时使用的最近 brief 由 Mapper 在数据库侧按修改时间和 ID 倒序并 `LIMIT 1`，避免加载全部 brief 正文；生成依据 JSON 无法解析时仅记录 generation ID，保留原始异常 cause，HTTP 错误响应不返回原始创作内容。
- 生成稿仅在 `preview` 状态可首次采纳或拒绝；采纳支持 `replace` 和 `append`，已采纳记录重复请求直接返回当前结果，不会二次写入正文。重新生成会创建新的 generation/task，并保留原依据、合并本次反馈。
- Web 层将 `page=abc`、整数溢出等请求参数类型转换失败统一映射为 `BAD_REQUEST` 和 HTTP 400；候选状态竞争与 AI 任务取消竞争分别返回 `SETTING_CANDIDATE_CONFLICT`、`AI_TASK_STATE_CONFLICT` 和 HTTP 409。
- 当前主流程数据流为：作品/章节创建 -> 章节共创消息沉淀 -> brief 与大纲收束 -> 章节生成记录 -> 用户采纳后写回 `chapters.content` -> 更新章节摘要、关键事件、设定候选和伏笔线索。
- 章节正文以 `chapters.content` 作为唯一事实源；生成记录、brief、大纲和知识层记录均围绕章节正文提供过程记录或上下文辅助。
- 当前接口文档不覆盖：正式前端页面、真实 AI 自动抽取服务、角色状态快照、叙事线程、时间线、知识巡检、token 汇总、LLM 调用日志和独立 `suggestions` 接口。

## 数据库与持久化要点

- 当前数据库迁移由 `moqi-start/src/main/resources/db/migration` 下的 Flyway SQL 管理。
- 当前数据库结构说明统一看 `docs/2026-06-09-数据库设计.md`；迁移历史和设计调整记录统一看 `docs/数据库设计变更记录.md`。
- P0 主流程以 `works`、`chapters`、`chapter_conversations`、`chapter_conversation_messages`、`chapter_briefs`、`chapter_generations` 为已落库基础。
- 自 issue #18 起，新增数据库表默认使用 `id`、`gmt_create`、`gmt_modified` 作为基础字段；历史 V1-V3 中的 `created_at/updated_at` 通过增量迁移改名，不重写旧迁移。
- `chapter_outlines` 是正式章节大纲事实源，一章一条，使用 `outline_content JSON` 保存本章目标、场景、人物变化、节奏、约束和未决问题，并用 `revision` 支撑大纲乐观锁。
- `chapter_briefs` 仅表示 AI 或会话收束出的摘要、候选结构卡或中间结果，不作为正式章节大纲事实源。
- `user_configs` 是用户级通用配置表，首版用于承载模型配置、写作偏好、外观和同步配置；暂不单独设计 `model_providers`。
- `user_configs` 的首次创建从缺失态版本 `0` 推进到版本 `1`，并依靠用户、配置键和软删除标记的唯一约束阻止并发创建覆盖；后续更新使用当前行 `version` 作为条件执行原子更新；配置值使用结构化 JSON 解析和序列化。
- `ai_tasks` 承载 AI 回复、正文生成、大纲刷新等异步任务状态，供轮询和取消接口使用；取消采用任务版本与非终态条件执行原子更新，竞争失败后使用最新版本做有界重试。
- `setting_candidates` 是 `setting_entries.source_candidate_id` 的外键父表；候选确认事务必须先锁定候选行，再写入或更新正式设定，最后按锁定快照的 `pending/version/deleted` 条件更新候选状态。
- 自 issue #18 的后续迁移起，P0 主流程相关表统一补充中文表注释和字段注释，便于通过数据库工具直接理解表语义。
- 当前 P0 数据库不保留 `biz_id` 业务唯一 ID 列，统一使用自增 `id` 作为主键和关联键。
- issue #22 起，数据库补充长篇小说知识层最小结构：`setting_candidates` 保存待确认设定，`setting_entries` 保存正式作品级设定，`foreshadowing_items` 保存伏笔与线索，`chapter_summaries` 保存章节摘要，`chapter_key_events` 保存章节关键事件。
- `chapters.chapter_type` 用于区分 `dedication`、`prologue`、`chapter`、`epilogue`、`other`，导入既有小说时应保留献词、序幕、尾声等非标准正文块。

- `scripts/start-local-mysql.ps1` 用于启动本地 MySQL，`scripts/stop-local-mysql.ps1` 用于停止本地 MySQL。

- `scripts/verify-longzu-i-import.ps1` 用于从数据库按 `chapter_no` 还原《龙族Ⅰ-火之晨曦》的标题、章节类型和正文，并统计章节主流程表与知识层记录，验证导入是否完整。

## 当前已知限制

- 当前已实现健康检查、作品章节、章节共创、章节生成、正文读写、知识层、用户配置、模型状态和 AI 任务接口。`moqi-service` 负责软删除过滤、查询侧统计、章节编号、字数派生、默认工作区判定、共创上下文保存、大纲 revision 冲突控制、生成状态流转、正文版本条件更新、候选状态流转、配置安全与版本控制、任务状态校验和取消，持久化继续复用既有 V1-V8 表结构。
- 章节大纲保存要求客户端提交 `baseRevision`；当服务端 `revision` 已变化时返回 `OUTLINE_REVISION_CONFLICT`，由前端刷新后重试。大纲刷新接口仅生成确定性的草稿内容，不调用模型。
- 章节正文保存和生成稿采纳要求客户端提交 `baseVersion`；版本冲突返回 HTTP 409 和 `CHAPTER_VERSION_CONFLICT`，`data` 包含 `serverContent`、`version`、`serverSavedAt`。当前章节生成使用确定性本地实现，尚未接入真实模型、后台执行器或流式输出。
- 章节打开建议采用只读聚合：存在未处理 `preview` 生成稿时进入 `generation_preview`，否则正文非空时进入 `editor`，其余进入 `co_creation`。`source` 当前仅为兼容请求字段，不保存最近访问记录。
- 作品列表默认返回 20 条、最多 100 条并按修改时间倒序；章节列表按 `chapter_no` 升序。所有作品与章节查询默认排除 `deleted=1`，不存在或已删除资源分别返回 `WORK_NOT_FOUND`、`CHAPTER_NOT_FOUND`。
- 当前数据库已有 P0 主流程与第一版必通知识层表，但角色状态快照、叙事线程、时间线事件和知识巡检结果尚未落库。
- 《龙族Ⅰ-火之晨曦》导入脚本属于本地验证脚本，不提交小说原文，也不代表正式 AI 自动抽取服务已经完成。
- `ai_tasks.result_suggestion_id` 是预留字段，当前没有 `suggestions` 表，不应生成当前阶段的独立建议接口。
- 模型状态接口不验证远端模型真实可用性；在没有独立安全密钥存储前，模型配置只保存非敏感元数据，因此不会将 `available` 报告为 `true`。
- token 汇总、LLM 调用日志、复杂检索增强和平台化权限能力属于后续增强范围。
